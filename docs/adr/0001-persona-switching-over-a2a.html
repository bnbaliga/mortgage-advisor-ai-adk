ADR-0001: Persona Switching Over Agent-to-Agent Routing

Status

Accepted

Date

2026-11-01

Context

We need to implement a multi-agent system where callers can be routed between: - Sam (Triage Agent) - Initial greeting and routing - Mac (Origination Agent) - New loan inquiries - Ivy (Servicing Agent) - Existing loan management

Google ADK supports two patterns for multi-agent systems:

  1. Agent-to-Agent (A2A): Multiple distinct agents with separate contexts, handoff via explicit transfer
  2. Dynamic Persona: Single agent with instruction function that changes personality/tools based on state

Decision

We chose Dynamic Persona Switching over Agent-to-Agent routing.

Implementation

# Single agent with dynamic instruction
root_agent = Agent(
    model=Gemini(...),
    name="mortgage",
    instruction=instruction,  # Function called each turn
    tools=ALL_AGENT_TOOLS,    # All 29 tools registered
    before_tool_callback=mortgage_gate,
    after_tool_callback=audit,
)

# instruction() returns different prompts based on CallState.active_agent
def instruction(ctx: ReadonlyContext) -> str:
    call = get_call_state(ctx.session.id)
    if call.active_agent == "origination":
        return MAC_PERSONA
    elif call.active_agent == "servicing":
        return IVY_PERSONA
    else:
        return SAM_PERSONA

Consequences

Positive

  • Seamless voice transfer: No audio gap when switching agents
  • Shared context: Conversation history preserved across personas
  • Simpler state management: One session, one agent instance
  • Faster transfers: Just update CallState.active_agent, next turn uses new persona

Negative

  • Tool coupling: All 29 tools registered on single agent (mitigated by policy door access control)
  • Larger prompt: Each persona instruction included in context
  • Less isolation: Agents share token budget (mitigated by context compression)

Mitigations

  • Policy door enforces tool access per agent (Sam can’t use get_loan_balance)
  • Context compression at 100k tokens keeps budget manageable
  • Clear persona boundaries in instruction text prevent cross-contamination

Alternatives Considered

Option 2: Agent-to-Agent (Rejected)

# Would require 3 separate agents with explicit handoff
sam_agent = Agent(name="sam", tools=TRIAGE_TOOLS, ...)
mac_agent = Agent(name="mac", tools=ORIGINATION_TOOLS, ...)
ivy_agent = Agent(name="ivy", tools=SERVICING_TOOLS, ...)

Rejected because: - Audio gap during agent switch (500ms+ latency spike) - Context lost on transfer (would need explicit context passing) - More complex session management (3 agents per call)
