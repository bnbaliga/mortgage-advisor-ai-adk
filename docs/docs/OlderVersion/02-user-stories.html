User Stories and Acceptance Criteria

HomeFirst AI Mortgage Advisor

Epic 1: Caller Triage and Routing

US-1.1: Initial Greeting

As a caller I want to be greeted professionally when I call So that I know I’ve reached the right company and can explain my needs

Acceptance Criteria: - [ ] System answers within 2 seconds of connection - [ ] Greeting includes company name “HomeFirst” - [ ] Agent introduces themselves by name - [ ] Caller is asked about the purpose of their call - [ ] System handles interruptions gracefully

Test Scenarios: | Scenario | Input | Expected Output | |———-|——-|—————–| | Normal greeting | Call connects | “Hi, this is Sam with HomeFirst…” | | Immediate interrupt | “I need help with my loan” | Stops greeting, acknowledges request |

US-1.2: Route to Origination

As a prospective borrower I want to be connected to a mortgage specialist So that I can get information about new loans

Acceptance Criteria: - [ ] System identifies new loan intent (“new loan”, “refinance”, “HELOC”) - [ ] Caller is transferred to Mac (origination agent) - [ ] No audio gap during transfer - [ ] Mac introduces themselves appropriately

Test Scenarios: | Scenario | Input | Expected Output | |———-|——-|—————–| | HELOC request | “I want a home equity line” | Transfer to Mac | | Refinance request | “Looking to refinance” | Transfer to Mac | | Ambiguous | “Tell me about your loans” | Clarifying question or transfer |

US-1.3: Route to Servicing

As an existing borrower I want to be connected to account services So that I can manage my current mortgage

Acceptance Criteria: - [ ] System identifies servicing intent (“my loan”, “payment”, “balance”) - [ ] Caller is transferred to Ivy (servicing agent) - [ ] No audio gap during transfer - [ ] Ivy asks for verification

Test Scenarios: | Scenario | Input | Expected Output | |———-|——-|—————–| | Payment request | “I want to make a payment” | Transfer to Ivy | | Balance inquiry | “What’s my balance?” | Transfer to Ivy | | Account question | “Question about my mortgage” | Transfer to Ivy |

Epic 2: Mortgage Origination

US-2.1: HELOC Eligibility Check

As a prospective HELOC borrower I want to know if I’m eligible for a HELOC in my state So that I don’t waste time if there are restrictions

Acceptance Criteria: - [ ] System asks for property state - [ ] Texas restrictions explained (primary residence only, once per year) - [ ] California restrictions explained if applicable - [ ] Ineligible callers offered alternatives - [ ] State rules cited from regulations

Test Scenarios: | Scenario | Input | Expected Output | |———-|——-|—————–| | TX primary residence | State: TX, Type: Primary | Eligible with restrictions | | TX rental property | State: TX, Type: Rental | Not eligible, explain why | | CA normal | State: CA | Eligible | | Unknown state | State: XY | “I don’t have rules for that state” |

US-2.2: Rate Estimate

As a prospective borrower I want to get an estimated interest rate So that I can compare options and plan my budget

Acceptance Criteria: - [ ] System asks for credit score range - [ ] System asks for LTV or property details - [ ] Rate returned with disclaimer “estimates only” - [ ] Rate based on current rate sheet - [ ] Multiple scenarios compared if requested

Test Scenarios: | Scenario | Input | Expected Output | |———-|——-|—————–| | Excellent credit | Credit: 780, LTV: 60% | Rate: 6.25% (estimate only) | | Good credit | Credit: 720, LTV: 75% | Rate: 6.75% (estimate only) | | High LTV | Credit: 750, LTV: 90% | Higher rate or PMI mention |

US-2.3: Equity Calculation

As a homeowner I want to know how much equity I have So that I understand my borrowing power

Acceptance Criteria: - [ ] System asks for home value - [ ] System asks for current mortgage balance - [ ] Equity calculated: Value - Balance - [ ] Max borrowing at 80% CLTV calculated - [ ] Results explained clearly

Test Scenarios: | Scenario | Input | Expected Output | |———-|——-|—————–| | Significant equity | Value: $500K, Balance: $200K | Equity: $300K, Max: $200K | | Low equity | Value: $400K, Balance: $350K | Equity: $50K, Limited options |

US-2.4: Register as Lead

As a interested prospective borrower I want to leave my contact information So that a loan officer can follow up with me

Acceptance Criteria: - [ ] System collects name and phone number - [ ] Email is optional - [ ] Lead registered with intent (HELOC, refi, purchase) - [ ] Confirmation provided to caller - [ ] Lead available for LO follow-up

US-2.5: Transfer to Loan Officer

As a qualified prospect I want to speak with a licensed loan officer So that I can proceed with an application

Acceptance Criteria: - [ ] System confirms transfer request - [ ] Business hours: Warm transfer to available LO - [ ] After hours: Lead captured for callback - [ ] Context passed to LO (what caller discussed)

Epic 3: Loan Servicing

US-3.1: Basic Identity Verification

As a returning borrower I want to verify my identity quickly So that I can access my account information

Acceptance Criteria: - [ ] System asks for full name - [ ] System asks for last 4 digits of phone - [ ] Match confirmed against customer record - [ ] Non-match handled gracefully (up to 3 attempts) - [ ] Lockout after 3 failures

Test Scenarios: | Scenario | Input | Expected Output | |———-|——-|—————–| | Correct info | Name: John Smith, Phone: 1234 | Verified, basic access granted | | Wrong phone | Name: John Smith, Phone: 9999 | “That doesn’t match”, retry | | 3 failures | 3 wrong attempts | Locked, transfer to LO |

US-3.2: Strong Identity Verification

As a borrower making account changes I want to complete additional verification So that my account is protected from unauthorized changes

Acceptance Criteria: - [ ] Required before payments, autopay, date changes - [ ] System asks for date of birth - [ ] System asks for approximate loan balance - [ ] Balance must match within $5,000 - [ ] Lockout after 3 failures

US-3.3: Check Loan Balance

As a borrower I want to check my current balance So that I know how much I owe

Acceptance Criteria: - [ ] Requires basic verification - [ ] Shows current principal balance - [ ] Shows next payment amount and due date - [ ] Shows escrow balance if applicable

US-3.4: View Payment History

As a borrower I want to see my recent payments So that I can verify my payment record

Acceptance Criteria: - [ ] Requires basic verification - [ ] Shows last 6 payments by default - [ ] Includes date, amount, method for each - [ ] Can request more history (up to 12 months)

US-3.5: Make One-Time Payment

As a borrower I want to make a payment over the phone So that I can pay my mortgage conveniently

Acceptance Criteria: - [ ] Requires strong verification - [ ] Shows available payment methods - [ ] Confirms amount, method, date - [ ] Reads back details for authorization - [ ] Requires explicit “yes” to proceed - [ ] Provides confirmation number

Test Scenarios: | Scenario | Input | Expected Output | |———-|——-|—————–| | Bank payment | $1500 from Chase ****5678 | “So that’s $1500… Do I have authorization?” | | Confirmed | “Yes” | “Payment processed, confirmation ABC123” | | Declined | “No” / “Wait” | “No problem, payment cancelled” |

US-3.6: Manage Autopay

As a borrower I want to set up automatic payments So that I never miss a payment

Acceptance Criteria: - [ ] Requires strong verification - [ ] Can enroll with existing payment method - [ ] Can set payment date (1st-28th) - [ ] Shows confirmation of enrollment - [ ] Can cancel autopay - [ ] Can modify autopay settings

US-3.7: Change Payment Date

As a borrower I want to change my payment due date So that it aligns with my pay schedule

Acceptance Criteria: - [ ] Requires strong verification - [ ] New date must be 1st-28th - [ ] Effective date communicated - [ ] One change allowed per 12 months (if applicable)

US-3.8: Secure Card Entry

As a borrower adding a card I want to enter my card number securely So that my card information is protected

Acceptance Criteria: - [ ] Card numbers NEVER spoken to AI - [ ] System prompts for keypad entry - [ ] DTMF tones captured securely - [ ] Card masked in confirmation (****1234) - [ ] PCI-DSS compliant handling

Epic 4: Compliance and Security

US-4.1: Rate Disclaimers

As a regulator I want rate estimates to include disclaimers So that borrowers understand rates are not locked

Acceptance Criteria: - [ ] Every rate response includes “estimates only” disclaimer - [ ] Disclaimer states rates subject to change - [ ] Disclaimer states not an offer of credit

US-4.2: State Rule Enforcement

As a compliance officer I want state-specific rules enforced automatically So that we avoid regulatory violations

Acceptance Criteria: - [ ] Texas HELOC rules enforced (primary only, once/year) - [ ] California rules enforced - [ ] Florida rules enforced - [ ] Unknown states fail closed (no approval) - [ ] Rules cited with regulatory references

US-4.3: PII Protection

As a security officer I want PII redacted from all logs So that we protect customer privacy

Acceptance Criteria: - [ ] Names redacted in logs - [ ] Phone numbers redacted in logs - [ ] DOB redacted in logs - [ ] Card numbers never stored - [ ] SSN never collected by voice

US-4.4: Verification Lockout

As a security officer I want accounts locked after failed verifications So that we prevent unauthorized access

Acceptance Criteria: - [ ] 3 failed verifications trigger lockout - [ ] Lockout persists for entire call - [ ] Caller informed of lockout - [ ] Transfer to loan officer offered - [ ] Lockout logged for security review
